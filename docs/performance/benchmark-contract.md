# API performance evidence contract

Release comparisons use schema-version 2 benchmark artifacts generated by
`npm run bench:api`. Each raw run records the exact Node runtime, platform,
architecture, concurrency, sample count, Git state, SQLite byte size and SHA-256,
runtime-source SHA-256, and Ontology snapshot byte size and SHA-256. Both
snapshots are copied before the server starts; hashes describe those exact
copies, not a source file that could change during the run.

The release gate is fail-closed:

- each route has at least 60 sequential and 60 concurrent observations;
- concurrency is exactly 20;
- baseline and current each aggregate at least three runs by median;
- runtime, SQLite identity, Ontology identity, sample count, concurrency, and
  route sets match across all raw runs and both aggregates; raw runs must also
  share one runtime-source hash, and a run fails if source files change while it
  is executing;
- the route set includes valuation dashboard, LSEG valuation summary at 300
  price points, LSEG full valuation at 900 price points, gurus, compact
  backtests, Ontology overview, and graph;
- response status, semantic SHA-256, compression with `Vary: Accept-Encoding`,
  conditional 304 behavior, and request counts are validated before latency;
- a single API request has a 120-second hard timeout; timeout fails the run and
  never omits the route or emits a partial artifact;
- no route may regress concurrent p95 by more than 5%; `--mode regression` stops
  there for ordinary release checks, while the default `--mode optimization`
  additionally requires at least one route to improve concurrent p95 by 30% or
  more.

Use immutable source snapshots. The benchmark copies SQLite into a temporary
directory before starting the server and never points the server at the source
database. Run each revision three times, summarize it, then compare aggregates:

```bash
npm run bench:api -- --database /absolute/guru-analysis.sqlite --ontology /absolute/ontology-snapshot.sqlite --label baseline --output /tmp/baseline-1.json
npm run summarize:performance -- --input /tmp/baseline-1.json,/tmp/baseline-2.json,/tmp/baseline-3.json --output /tmp/baseline-median.json
npm run check:performance -- --baseline /tmp/baseline-median.json --current /tmp/current-median.json --mode regression
```

The recorded `databaseBytes`, `databaseSha256`, `ontologyBytes`, and
`ontologySha256` fields are the authoritative input identity; the summarizer and
gate reject any mismatch instead of producing a comparison.
