1. What This Module Is

The current LSEG module is a platform-native stock module inside the buy-side
fundamental-analysis application. It is not a standalone page and it is not a
pure moat-score model.

LSEG is loaded through:

- src/stocks/registry.ts
- src/stocks/lseg/config.ts
- src/stocks/lseg/dashboard.tsx

The module contract remains:

- data
- calculateSummary
- calculateValuation
- Dashboard
- valuationConfig

The dashboard now consumes data through module.data. The default dataset is
still lsegMockData, but the page no longer bypasses the module contract when it
builds dashboard outputs or interactive valuation outputs.

- 2026 company guidance anchors

Assumptions:

- WACC inputs
- target P/E

- terminal growth
- buyback timing and execution price
- strategic split assumptions
- some peer guardrails

Derived outputs:

- segment revenue forecasts
- margin bridges

- buyback share-count bridge
- DCF
- operating SOTP

Placeholders / manual analyst inputs that still need caution:

5. Valuation Methods

A. Forward P/E

- Formula: forward adjusted EPS × target P/E
- Role: base valuation method
- Included in base blended fair value

B. FCF Yield

- Formula: forward equity FCF per share / target FCF yield
- Role: base valuation method
- Included in base blended fair value

C. DCF

- Formula: unlevered FCF discounted at WACC
- Net debt and minority interest are subtracted after enterprise value
- Role: base valuation method
- Included in base blended fair value

DCF taxonomy:

- DCF method: WACC / unlevered FCF
- FCF used in DCF: unlevered FCF
- FCF used in FCF yield: equity FCF
- Interest expense is not deducted inside DCF unlevered FCF
- Net debt is deducted after enterprise value

D. Operating SOTP

- Role: base valuation method
- Included in base blended fair value
- Uses reported_2025 taxonomy by default

Reported operating taxonomy:

- Data & Analytics
- FTSE Russell
- Risk Intelligence
- Markets
- Other

Important:

- Markets already includes the relevant trading / clearing / post-trade economics
- operating SOTP does not separately capitalize Post Trade unless there is an
  explicit split and the model is intentionally moved into strategic analysis

E. Strategic / Activist SOTP

- Role: optionality / activist / portfolio review case
- Not included in base blended fair value
- Built as incremental optionality on top of the selected operating SOTP

Strategic optionality can include:

- Tradeweb look-through uplift
- post-trade standalone uplift
- portfolio simplification uplift
- excess capital return uplift
- tax leakage
- dis-synergy cost
- execution discount

F. Blended Fair Value

The module shows multiple blended views:

- core value ex-SOTP
- 25% SOTP uplift blend
- 50% SOTP haircut blend
- 75% SOTP uplift blend
- full selected-policy operating SOTP blend

The recommended fair value is confidence-based. If SOTP confidence is too low,
the module will not recommend the full operating SOTP blend as the primary
underwriting anchor.

G. Probability-Weighted Fair Value

- Role: overlay / diagnostic
- Not a base valuation method
- Scenario probabilities are influenced by diagnostics, not by hidden
  valuation-mechanic uplifts

6. SOTP Structure

The SOTP module has three layers:

- operatingSotp
- strategicSotp
- sotpAudit

Operating SOTP:

- going-concern value
- uses reported taxonomy
- no separate Post Trade value unless explicitly split and disclosed

Strategic SOTP:

- activist / optionality layer
- built as incremental uplift over the selected operating SOTP
- not part of the default base blend

SOTP audit:

- segment EBITDA used
- EBITDA year used
- multiple used
- peer group
- source
- placeholder / stale / manual flags
- ownership / NCI bridge
- corporate reconciliation
- warnings and confidence caps

7. Confidence and Integrity Scores

The current model separates:

- overallIntegrityScore
- sotpIntegrityScore
- sotpConfidenceScore
- dataQualityScore
- recommendedValuationConfidence

Meanings:

- overallIntegrityScore: full-model mechanics
- sotpIntegrityScore: SOTP bridge / taxonomy / double-count correctness
- sotpConfidenceScore: SOTP data confidence
- dataQualityScore: manual / stale / placeholder data quality
- recommendedValuationConfidence: confidence in the selected primary valuation
  anchor

Important:

- low SOTP confidence should push the recommended valuation anchor toward
  coreValueExSotp or a haircut-SOTP bridge
- high full-SOTP values are shown, but they are not automatically the model's
  primary underwriting value

8. Consensus and Market-Implied Diagnostics

The current architecture includes:

- consensusComparisonEngine
- marketImpliedValuationEngine

Consensus comparison is used to compare the model against a manually updateable
consensus snapshot. It is a comparison layer, not a valuation method.

Market-implied diagnostics are used to infer what the current price implies for:

- forward P/E
- FCF yield
- EV / EBITDA
- terminal growth
- WACC
- FCF/share CAGR
- exit multiple

These are diagnostics, not standalone fair-value methods in the base blend.

10. Limitations

This is a strong institutional underwriting module, but it is not a live-data
system yet.

Main limitations:

- underlying operating data still defaults to lsegMockData
- peer data is manually curated, not API-fed
- some peer sets are incomplete
- ownership / NCI bridge still contains residual fallback items
- strategic split still relies partly on analyst estimates
- tradewebMonthly is a structured placeholder read-through

Therefore:

- full operating SOTP should not be treated as investment-grade primary fair
  value unless confidence improves
- strategic SOTP should be treated as optionality only
- recommended fair value should be interpreted through the confidence-adjusted
  valuation bridge, not through the most optimistic headline number
